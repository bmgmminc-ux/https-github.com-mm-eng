# 검토 — 다우오피스 웍스 31개 앱을 이 프로그램으로 가져오기

작성 2026-09-24 · 대상 myungmoon.netlify.app (단일 HTML + Supabase) · 근거 = 대표가 보낸 웍스 홈 화면 8장(A~G 7분류 31개 앱)
전제 = 2026-06-18 대표 결정 "다우 메뉴는 이 앱으로 이전(메뉴별 데이터 업로드 → 기능 하나씩)" · 그때 걸었던 조건(회사 기준 RLS + 역할)은 R1~R3(2026-09-13~16)로 충족됨.

## 1. 결론

- **가져올 수 있다. 31개 중 29개.** 나머지 2개(ID 관리 대장 2종)는 비밀번호 저장소라 이 앱에 넣으면 안 된다.
- 29개는 세 갈래로 나뉜다. ① **기존 모듈에 흡수** 9개 — 이미 있는 거래처·현장·매입·일용직·출역에 데이터만 올린다. ② **공통 대장(장부) 엔진으로 구성** 15개 — 웍스 앱은 전부 "필드 몇 개짜리 목록"이라, 대장 화면 하나를 만들고 앱마다 필드 정의만 얹으면 된다. ③ **자료실(파일)** 5개 — 카탈로그·소식지·가격정책 자료·사이트 목록.
- 새로 만드는 코드는 사실상 **대장 엔진 1개 + 자료실 1개**다. 앱 15개를 따로 만들지 않는다. 단일 HTML 비대화도 그 범위에서 멈춘다.
- 순서는 직원 입력이 많은 현장 대장(업무 보고서·A/S 접수·분할납품요구서)부터. 흡수 이관 9개는 데이터 대조가 일이지 개발이 아니다.

## 3. 어떻게 만드는가 — 대장 엔진

지금 앱은 현장·매입·기성처럼 표마다 화면을 따로 만들었다. 웍스의 앱들은 그럴 필요가 없다. 목록 + 입력 폼 + 상세 + 첨부 + 필터가 전부이고 다른 것은 필드 이름뿐이다.

- **저장**: 표 하나 `ledger_rows(id, company_id, app_key, project_id, client_id, data jsonb, status, created_by, updated_at …)`. 앱 정의(`app_key`별 이름·분류·필드 목록·현장 연결 여부·관리자 전용 여부)는 앱 코드 안의 레지스트리로 시작한다. 앱을 하나 더 얹을 때 DB를 건드리지 않는다.
- **화면**: 대장 화면 하나가 정의를 읽어 목록·검색·정렬·행 입력·상세·첨부·CSV 업로드를 그린다. 사이드바에는 A~G 대분류가 도메인으로 붙고, 역할에 맞는 것만 보인다(2026-06 도메인 허브 결정과 같다).
- **권한**: R1 헬퍼(같은 회사·역할) 그대로. 관리자 전용 앱은 정책이 `app_key`로 걸러 직원에게는 행을 보내지 않는다 — R2와 같은 원칙("보여주지 않을 것은 서버가 보내지 않는다").
- **동시 입력**: 2단계에서 만든 행 단위 upsert(client_id) 방식을 그대로 쓴다. 대장은 여러 사람이 동시에 넣는 곳이다.
- **첨부**: 기존 첨부 저장소 경로를 재사용한다(`ledger/<app>/<row>/…`). 직원 다운로드 금지(R3)는 첨부 열람과 별개로 그대로 둔다.
- **자료실**: 파일 목록 + 분류 + 관리자 전용 표식. 뷰어는 진입 시 지연 로딩.
- **흡수 9개**: 기존 CSV 업로드 엔진(거래처·일용직·출역·매입)에 웍스 내보내기 열 순서를 맞춰 올린다. 코드보다 열 대조가 일이다.

## 5. 리스크 — 먼저 정해야 하는 것

1. **주민번호(D-5)**: 감사에서 이미 지적된 평문 저장 상태로는 이관하면 안 된다. 뒷자리 마스킹 저장(앞 6자리 + 성별 1자리만)이면 노무 신고 서류에는 부족하고, 전체를 두려면 암호화 컬럼이 필요하다. 어느 쪽인지 대표 결정.
2. **계좌·통장(C-4)**: 관리자 전용 + 계좌번호 마스킹 표시. 원본은 서버에만.
3. **ID·비밀번호(F-1·F-4)**: 이 앱에 두지 않는다. 브라우저 저장소에 내려오는 구조라 한 번 새면 끝이다. 조직용 비밀번호 관리자(예: Bitwarden 조직 요금제)로 옮기고, 앱에는 사이트 이름·용도·담당자만 둔다.
4. **첨부 파일**: 웍스 엑셀 내보내기에는 파일이 따라오지 않는다. 앱별 첨부 건수를 0단계에서 세고, 많으면 재업로드 계획을 따로 잡는다. Supabase 저장소 무료 한도(1GB)도 같이 본다.
5. **현장 연결 키**: 웍스의 현장명은 자유 텍스트일 가능성이 높다. 현장 코드(명문-xxxx) 대응표를 0단계에서 만든다. 대응 안 되는 행은 '미연결'로 올리고 화면에서 고른다.
6. **단일 HTML 크기**: 대장 엔진은 정의 기반이라 앱 15개가 늘어도 코드는 조금 는다. 자료실 뷰어와 큰 표는 지연 로딩.

## 6. 대표가 정할 것

- 이관 순서 동의(제안: 2단계 현장 대장부터).
- ID 관리 대장 2종 제외 동의.
- 주민번호·계좌번호 저장 방식(5절 1·2).
- 웍스 계약 종료 시점 — 5단계까지 끝난 뒤 한 달 병행이면 충분하다.

다음 행동은 0단계다. 대표가 웍스에서 앱별 엑셀을 내보내 폴더 하나에 모아 주면, 필드·건수 표를 만들어 1단계 설계로 들어간다.
